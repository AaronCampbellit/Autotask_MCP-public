# Business MCP domain pack

This package exposes a finite, reviewed subset of Autotask REST resources through `packages/business/src/index.ts` and `packages/business/src/tools.ts`. Every route is derived from the official entity documentation and every response is projected to an allowlist. Current tenant field metadata is required before a query or mutation. Company, project, contract, task, configuration-item and purchase-order parents are fetched and checked before child records are returned or changed.

Checklist CRUD is provided by the separate bounded work-management/checklist pack, not this business pack; checklist libraries/templates remain out of scope. Contact support remains lookup and ticket linking only; general contact or company administration is not exposed.

The documented route references used for this pack are:

- [Contracts](https://www.autotask.net/help/developerhelp/Content/APIs/REST/Entities/ContractsEntity.htm), [Contract services](https://www.autotask.net/help/developerhelp/Content/APIs/REST/Entities/ContractServicesEntity.htm), [Contract blocks](https://www.autotask.net/help/developerhelp/Content/APIs/REST/Entities/ContractBlocksEntity.htm), [Contract charges](https://www.autotask.net/help/developerhelp/Content/APIs/REST/Entities/ContractChargesEntity.htm), [Contract service adjustments](https://www.autotask.net/help/developerhelp/Content/APIs/REST/Entities/ContractServiceAdjustmentsEntity.htm), and [Invoices](https://www.autotask.net/help/developerhelp/Content/APIs/REST/Entities/InvoicesEntity.htm)
- [Projects](https://www.autotask.net/help/developerhelp/Content/APIs/REST/Entities/ProjectsEntity.htm), [Phases](https://www.autotask.net/help/developerhelp/Content/APIs/REST/Entities/PhasesEntity.htm), [Tasks](https://www.autotask.net/help/developerhelp/Content/APIs/REST/Entities/TasksEntity.htm), and [Task predecessors](https://www.autotask.net/help/developerhelp/Content/APIs/REST/Entities/TaskPredecessorsEntity.htm)
- [Configuration items](https://www.autotask.net/help/developerhelp/Content/APIs/REST/Entities/ConfigurationItemsEntity.htm), [DNS records](https://www.autotask.net/help/developerhelp/Content/APIs/REST/Entities/ConfigurationItemDnsRecordsEntity.htm), [configuration-item notes](https://www.autotask.net/help/developerhelp/Content/APIs/REST/Entities/ConfigurationItemNotesEntity.htm), and [Subscriptions](https://www.autotask.net/help/developerhelp/Content/APIs/REST/Entities/SubscriptionsEntity.htm)
- [Products](https://www.autotask.net/help/developerhelp/Content/APIs/REST/Entities/ProductsEntity.htm), [Inventory products](https://www.autotask.net/help/developerhelp/Content/APIs/REST/Entities/InventoryProductsEntity.htm), [Inventory items](https://www.autotask.net/help/developerhelp/Content/APIs/REST/Entities/InventoryItemsEntity.htm), [Inventory transfers](https://www.autotask.net/help/developerhelp/Content/APIs/REST/Entities/InventoryTransfersEntity.htm), [Purchase orders](https://www.autotask.net/help/developerhelp/Content/APIs/REST/Entities/PurchaseOrdersEntity.htm), [purchase-order items](https://www.autotask.net/help/developerhelp/Content/APIs/REST/Entities/PurchaseOrderItemsEntity.htm), and [purchase receiving](https://www.autotask.net/help/developerhelp/Content/APIs/REST/Entities/PurchaseOrderItemReceivingEntity.htm)

The operation ledger is deliberately narrower than the documentation. All business-pack reads require `operational.read` and `finance.read`; all mutations additionally require `finance.write` plus the relevant domain capability (`projects.write`, `procurement.write` or `configuration.write`). Contract, project and product CRUD only permits fields in the package allowlist. Fields marked `create_only` in `business_schema` are accepted on create when native documentation requires or permits them, and are rejected on update even if tenant metadata reports them writable. Invoices support context reads, the documented `invoiceNumber`/`paidDate`/`webServiceDate` update, and the dedicated `Invoices/{id}/InvoicePdf` read export; posting, approval, delivery and payment operations are not exposed. Subscription create is disabled because the captured documentation marks it unresolved. `TaskPredecessors` updates accept `lagDays` only and reject relationship changes. Stock add/remove/transfer commands are write-only command routes with native `quantityBeingAdded`, `quantityBeingRemoved` and `quantityBeingTransferred` request fields; no synthetic balance or rollback operation is offered. Service adjustment and service bundle adjustment endpoints are also write-only because the captured contract has no read route. `billing_true_up` returns effective-dated service/unit evidence and explicitly does not calculate or apply a charge.

All writes reserve an encrypted intent before dispatch, require fresh identity and capability checks, and use `ImpersonationResourceId`. Writes with a documented read route read back the saved native record; write-only adjustment and stocked-item commands remain `accepted_unverified` because the API provides no safe readback route. A transport timeout or incomplete readback produces `unknown_outcome` or `accepted_unverified`; the engine never automatically repeats it. Cursors are encrypted and bound to actor identity, policy, filters, entity and page size.

CRM to-dos and project/task note tools are documented in [CRM to-dos and notes](CRM-TODOS-AND-NOTES.md).
